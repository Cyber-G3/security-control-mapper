# SpectraSec Security Control Mapper

Open-source, deterministic mapping engine that relates technical security findings and evidence to control references across multiple frameworks.

> Development status: **Alpha / v0.1-dev**

## Goal

Translate technical findings into structured control references without claiming regulatory compliance or certification.

```text
Finding / Evidence
      ↓
Normalized finding type or source check ID
      ↓
Versioned mapping dataset
      ↓
ISO 27001 / NIS2 / ENS / SOC 2 references
      ↓
Coverage context + evidence needs
```

## Current scope

The current mapping dataset covers repository/security findings including branch protection, required pull-request reviews, secret scanning and repository security policy. Each mapping can include supporting references for ISO/IEC 27001:2022, NIS2, ENS and SOC 2.

ENS references are contextual supporting mappings based on Real Decreto 311/2022. Applicability depends on the system category, security dimensions and organizational context; a repository configuration does not itself prove or disprove ENS compliance.

## CLI

```bash
control-map list-findings
control-map map branch-protection-disabled
control-map map secret-scanning-disabled --json
```

Batch CSV/JSON input is supported:

```bash
control-map map-file findings.csv
control-map map-file findings.json --output mapped-controls.json
```

## Security Evidence Collector integration

The mapper can ingest `findings/findings.json` generated by `security-evidence-collector` directly:

```bash
control-map map-collector ./evidence-pack-UUID/findings/findings.json
control-map map-collector ./evidence-pack-UUID/findings/findings.json --output control-mappings.csv
```

Source metadata is preserved where available:

```text
finding_id
check_id
severity
```

This creates the first direct interoperability path in the SpectraSec toolchain:

```text
security-evidence-collector
          ↓
      findings.json
          ↓
security-control-mapper
          ↓
ISO 27001 / NIS2 / ENS / SOC 2 supporting references
```

Unknown source check IDs are not silently converted into compliance gaps; they are skipped by collector batch ingestion until a documented mapping exists.

## Design principles

- deterministic mappings
- versioned datasets
- source provenance preserved
- framework references separated from compliance conclusions
- explicit evidence requirements
- no LLM dependency at runtime
- machine-readable JSON/CSV output

## Frameworks

Current framework coverage:

- ISO/IEC 27001:2022 / Annex A references
- NIS2 supporting references
- ENS supporting references
- SOC 2 Trust Services Criteria supporting references

Mappings indicate potential relevance only. They are not legal determinations, audit conclusions or statements of framework equivalence.
